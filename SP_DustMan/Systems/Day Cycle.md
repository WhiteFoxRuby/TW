# Day Cycle — дневной цикл и тайм-слоты

> [!summary]
> День состоит из **4 тайм-слотов** (Утро, День, Вечер, Ночь) с переменной стоимостью действий: вылазка = 2 слота, ремонт = 1, продажа = 1. **Ни один день не вмещает всё** — дефицит времени и есть двигатель решений (модель Recettear). Поверх дня — недельный цикл (аренда, обвал рынка, новые покупатели) и глобальный (зоны, предметы, техники, тайна черноты).

## Стоимость действий

| Действие | Слоты | Почему |
|---|---|---|
| Вылазка на свалку | **2** | Опасная, времязатратная работа |
| Рынок хлама | 1 | Утренний поход к старьёвщикам *(упрощение среза: в срезе рынок вместо вылазки)* |
| Ремонт одного предмета | **1** | Сосредоточенная работа за столом |
| Продажа (торговая сессия) | **1** | Открытие торгового окна |
| Социальное / сюжет / отдых | 1 | Ночь — сюжет, отдых, пассивные процессы |

Типичные дни: вылазка + продажа (3 слота, 1 на быстрый ремонт или общение); два ремонта + продажа (3); три ремонта без продажи — накопление запаса.

## Слоты по времени суток

| Слот | Обычное занятие |
|---|---|
| Утро | Рынок или вылазка |
| День | Ремонт |
| Вечер | Продажа или ремонт |
| Ночь | Сюжет, отдых, пассивные процессы (ванна для замачивания, распространение черноты) |

Привязка действий к слотам — мягкая: игрок сам распределяет 4 единицы времени.

## Циклы вокруг дня

| Цикл | Масштаб | Содержание |
|---|---|---|
| **Минутный** | секунды | Жест → реакция предмета → звук → удовлетворение ([[Systems/Gestures]]) |
| **Сессионный** | 15–30 мин | Один слот = одно действие; решение «что делать сейчас» |
| **Дневной** | 4 слота | См. выше |
| **Недельный** | 7 дней | Расходы (аренда); обвал рынка при перепродаже одного типа; новые покупатели и заказы; событие недели |
| **Глобальный** | вся игра | Новые зоны вылазок, типы предметов, техники ремонта; раскрытие тайны черноты |

### Нарастающее давление

Recettear использует еженедельные выплаты долга (от 10 000 до 500 000 пикс за пять недель). Эквивалент — **аренда мастерской**, расходы на чистящие средства или «взнос» в поселение. Давление должно быть достаточно твёрдым, чтобы предотвратить бесцельное хомячество, но достаточно мягким, чтобы позволить «потраченные впустую» дни на сюжет.

В срезе: аренда 150 в конце дня 7, **по умолчанию выключена** (`rentEnabled = false`). Режиссёр использует runway до аренды как главный сигнал давления ([[Director/Director#Индексы]]).

## Три зоны хаба

Дом, который растёт вместе с игроком ([[Design/Overview#Три зоны хаба]]): **мастерская** (верстак, инструменты, станции), **зона продаж** (витрина, доска объявлений), **жилые помещения** (кровать, кухня, блокнот, декор). Каждая зона — собственное дерево улучшений и собственная визуальная трансформация.

## Реализация в срезе

- Хаб — существующая side-scroll сцена `SampleScene` с тремя точками (`InteractivePoint`, клавиша **E**): **Рынок** и **Прилавок** открываются uGUI-оверлеями поверх хаба, **Верстак** — отдельная сцена `Workbench` (возврат по **Q**).
- HUD в хабе: день / слоты / деньги (`HubController`). Завершение дня — кнопка в хабе → сводка (потрачено / заработано / аренда) → новый день.
- Состояние дня живёт в статическом `GameState`:

```csharp
public static class GameState
{
    public static int Money, Day, SlotsLeft, SpentToday, EarnedToday;
    public static ItemInstance CurrentItem;              // максимум один в срезе
    public static readonly List<MarketOffer> MarketStock;

    public static bool TrySpendSlot(int cost, string reason = "");   // false, если слотов не хватает
    public static void RestockMarket();                              // план завоза от GameDirector
    public static DayResult EndDay();                                // аренда, сводка
    public static void StartNewDay();                                // Day++, слоты, OnDayStart режиссёра, завоз
}
```

- Слот ремонта списывается **при «Завершить ремонт»**, не при входе на верстак — известный вопрос ([[Reference/Open Questions#Когда списывать слот ремонта]]).
- Каждое списание слота пишется в телеметрию `SlotSpent` с причиной ([[Director/Director#Телеметрия]]).
- Сохранений в срезе нет; `GameState` живёт между сценами благодаря статике — см. риск domain reload в [[Reference/Architecture#Статика и Enter Play Mode]].
