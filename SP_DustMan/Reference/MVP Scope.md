# MVP Scope — вертикальный срез

> [!summary]
> Срез проверяет главную гипотезу игры: **жестовый ремонт за столом приятен сам по себе**. Всё остальное — обвязка, чтобы ремонт имел контекст (купил сломанное → починил → продал). Срез = один играбельный день: рынок → ремонт карманного фонаря по трём фазам → продажа. Если после сборки чинить фонарь скучно — меняем дизайн жестов, а не добавляем контент. Утверждён 2026-07-08; собран 2026-07-08 (вечер); ручная приёмка не проводилась.

## Границы скоупа

**Входит:**

- Один предмет: карманный фонарь (упрощённый Пример 1 из [[Systems/Repair#Процедуры ремонта — полные цепочки]]).
- 6 жестов: вращение, перетаскивание, протирка, качание, клик, зум ([[Systems/Gestures]]).
- 5 инструментов: отвёртка, плоскогубцы, тряпка, лупа, наждачка ([[Systems/Tools]]).
- Три фазы ремонта: Осмотр → Работа → Проверка.
- Рынок (покупка за деньги) и продажа (один покупатель, цена жестом по шкале).
- Дневной цикл из 4 тайм-слотов (упрощение: рынок = 1 слот вместо вылазки за 2).
- Деньги. Плейсхолдер-арт (цветные спрайты).

**Не входит (сознательно):** чернота, вылазки и раскопки, блокнот, апгрейды мастерской, типы покупателей (один универсальный), обвал рынка, аренда (флаг в конфиге, выключена), сохранения, пайка и точное перетаскивание (hold / drag по траектории), звук (этап опционален), геймпад и тач, локализация, Spine-анимации. AI-режиссёр — вне скоупа, но реализован по явному запросу владельца ([[Director/Director]]).

> [!important] Правило
> Отступления от полного дизайна помечены как «упрощение среза» — их можно оспаривать, но не расширять молча. Всё из списка «не входит» требует явного решения владельца проекта.

## Игровой цикл среза (walkthrough)

1. Игрок в хабе (side-scroll сцена `SampleScene`), 4 слота, 100 монет.
2. Точка **«Рынок»** (E) → оверлей: 2–3 фонаря с разными видимыми состояниями и ценами 15–25. Покупка списывает 1 слот и деньги.
3. Точка **«Верстак»** → сцена `Workbench`.
4. **Осмотр:** фонарь на столе, вращается перетаскиванием, зум колесом. Видимые дефекты заметны; скрытые — через лупу или после разборки. Маркеров «что сломано» нет.
5. **Работа:** разборка (отвёртка — вращение), устранение дефектов инструментами, сборка обратно.
6. **Проверка:** клик по кнопке фонаря. Все дефекты устранены → луч света, успех. Нет → симптом (не включается / тускло), возврат без штрафа. «Завершить ремонт» (E) списывает 1 слот.
7. Точка **«Прилавок»** → покупатель, шкала цены, реакция (доволен / думает / уходит), сделка. 1 слот.
8. Конец дня: сводка (потрачено / заработано), новый день.

## Контент среза

Фонарь: 5 модулей (корпус, линза, лампа + контакты, батарейный отсек, кнопка), 2–3 случайных дефекта из пула 5 — таблица в [[Systems/Items and Defects#Дефекты фонаря]].

### Баланс (черновые числа, конфиг в одном месте)

| Параметр | Значение |
|---|---|
| Стартовые деньги | 100 |
| Цена фонаря на рынке | 15–25 (хуже — дешевле) |
| Базовая цена починенного | 60 |
| Модификатор качества | ×0.7–1.3 |
| Слоты дня | 4; рынок 1, ремонт 1, продажа 1 |
| Аренда | 150 в конце дня 7, выключена |

Качество 0–100: 40 за все дефекты + 30 за чистоту + 30 минус штрафы за ошибки жестов. Реализация — [[Systems/Items and Defects#Качество и цена]]; все числа — [[Reference/Cheat Sheet]].

## Технический каркас

Unity 6000.3.8f1, URP 17.3, Input System 1.18 (использовать Input Actions, не сырой `Keyboard.current`). Данные — ScriptableObject в `Assets/Data/`; жесты — трекеры в `Assets/Scripts/Gestures/`; хаб — `SampleScene`, рынок и прилавок — оверлеи через `InteractivePoint` (E), верстак — сцена `Workbench` (возврат по Q). Все пороги и баланс — в конфигах, не в коде. Подробно — [[Reference/Architecture]].

### Судьба прототипа (этап 0)

Утечка `CreateWhiteSprite` → кэш в `SpriteUtils`; генерация уровня из `PlayerController` → `LevelBuilder`; позиция между сценами → `SceneCarry` вместо PlayerPrefs; `CameraFollow`, `InteractivePoint` переиспользованы; `AutoSprite` удалён; ввод — Input Actions. Всё выполнено.

## Этапы и критерии приёмки

Порядок жёсткий: каждый этап проверяется человеком до перехода к следующему; после этапа — запись в WORKLOG.

| Этап | Что | Приёмка | Реализация | Приёмка человеком |
|---|---|---|---|---|
| **0. Санация** | багфиксы прототипа | хаб не изменился, дублей нет, ввод через Input Actions, стрелки = WASD | ✅ | ⏳ |
| **1. Каркас данных** | SO-типы, `ItemInstance`, генератор | сцена `DataTest`: кнопка печатает состав; 20 генераций — разные комбинации | ✅ (авто: `DevChecks`) | ⏳ |
| **2. Жесты + дебаг-сцена** | все 6 жестов на голых прямоугольниках | сцена `GestureDebug` с индикаторами; **человек руками** подтверждает надёжность и отсутствие ложных срабатываний. **Ключевой этап — если жесты не ощущаются, дальше не идём** | ✅ | ⏳ |
| **3. Верстак** | фонарь на столе, инструменты, разборка/сборка, зум | полный цикл «разобрал — устранил окисление — собрал» мышью, без UI-кнопок | ✅ | ⏳ |
| **4. Фазы и дефекты** | осмотр без маркеров, лупа, 5 дефектов, проверка с симптомами, качество | фонарь «не включается» диагностируется и чинится без подсказок; недочиненный показывает правильный симптом | ✅ | ⏳ |
| **5. Экономика** | рынок, прилавок, шкала, реакция, деньги, слоты, сводка | полный день-цикл играется; «дешевле купить — лучше починить — дороже продать» даёт положительную маржу | ✅ | ⏳ |
| **6. Фидбек** (опц.) | плейсхолдер-звуки, твины реакции | субъективно «стало приятнее» | ⬜ | — |

Автоматически проверены: компиляция (Unity batchmode), загрузка данных и генератор (`DevChecks`). После сборки проведено адверсариальное ревью: 18 находок исправлено (дедзона вращения, сброс проверки при выкручивании, перекрут при затяжке, ПКМ-отмена, интерполяция протирки, восстановление прогресса по Q, клики сквозь uGUI и др.).

## Критерий готовности среза

Человек, не видевший доков, за **10 минут без объяснений** проходит день-цикл и правильно отвечает на вопрос «что ты делал?». После этого — плейтест-вопрос гипотезы: **«хочется починить второй фонарь?»**

- **Да** → расширяем контент: второй предмет — ожерелье ([[Systems/Repair#Пример 2: Ожерелье из пуговиц (текстиль + бытовое)]]).
- **Нет** → дизайн-итерация жестов, контент не добавляем.

## Правила для агента-разработчика

- Код — `Assets/Scripts/` (Core / Gestures / Workbench / Economy / Director / UI), данные — `Assets/Data/`. `ProjectDocs` Unity не импортирует — туда только документация.
- Все числа баланса и пороги жестов — в конфигах/SO, не в константах.
- Не расширять скоуп без явного решения владельца.
- После каждого этапа — запись в WORKLOG, при новых документах — обновить индексы.
- Термины — по [[Reference/Glossary]]; дизайн-контекст — [[Design/Overview]], [[Systems/Repair]].
